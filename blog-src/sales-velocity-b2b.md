# Sales Velocity — формула скорости B2B-выручки и 4 рычага роста

Если ты B2B-фаундер или VP Sales — это **первая** метрика на твоём dashboard. Sales Velocity объединяет 4 main драйвера sales-эффективности в одну цифру:

> **Sales Velocity = (Активные opportunities × ACV × Win Rate) / Длина цикла в днях**

Сколько долларов ARR ты генерируешь в день из текущего пайплайна.

## Зачем эта метрика

3 главных reasons:

1. **Forecasting** — multiply Sales Velocity на rest-of-quarter days → бюджетная projection
2. **Прioritization** — все 4 переменные actionable. Двигаешь любую → velocity растёт
3. **Сравнение каналов / сегментов** — Enterprise vs SMB Velocity, Outbound vs Inbound Velocity

## Пример расчёта

**B2B SaaS:**
- Активных opportunities: 50
- ACV (средний contract): $30k
- Win Rate: 25%
- Average cycle length: 60 дней

Sales Velocity = (50 × 30k × 0.25) / 60 = 375,000 / 60 = **$6 250 / день**

За квартал (90 дней): $562 500 ожидаемого New ARR.

## 4 рычага роста (важны не одинаково)

### Рычаг 1: Pipeline (Opportunities) — easiest to increase
- +50% opportunities = +50% velocity
- Каналы: SDR outbound, ABM, content/SEO, partnerships
- **Risk**: больше opportunities при низком Win Rate = wasted time

### Рычаг 2: ACV — самый высокий impact
- +20% ACV = +20% velocity (без дополнительной работы)
- Pricing review (every 12 мес обязательно)
- Upselling premium-tiers в первой сделке
- Multi-product bundling

### Рычаг 3: Win Rate — самый сложный
- +10pp Win Rate (e.g. 25%→35%) = +40% velocity
- Sales enablement, лучше discovery questions
- ICP-фокус (drop low-fit opps)
- Demo-quality (ROI calculator показанный в demo > generic feature tour)

### Рычаг 4: Cycle Length — недооценённый
- −20% cycle = +25% velocity
- Реже follow-ups (вместо «check in next week» — «I'll send you contract Friday EOD»)
- Procurement assistance (template MSA, security docs ready)
- Multi-threading (engage 3+ stakeholders с самого начала)

## Real-world: каков impact каждого рычага в %

Допустим Sales Velocity baseline = $5k/day.

| Change | New Velocity | Lift |
|--------|--------------|------|
| +25% opportunities (60→75) | $6.25k | +25% |
| +25% ACV ($30k→$37.5k) | $6.25k | +25% |
| +25% Win Rate (25%→31%) | $6.25k | +25% |
| −25% cycle length (60d→45d) | $6.67k | +33% |
| **Все 4 одновременно** | $13k | **+160%** |

Cycle Length — самый высокий impact на equal % change. Часто игнорируется потому что не intuitive.

## Бенчмарки по сегментам

| Сегмент | Cycle Length | Win Rate | ACV |
|---------|--------------|----------|-----|
| SMB / PLG | <30 дней | 30-40% | $1-10k |
| Mid-market | 30-90 дней | 20-30% | $10-100k |
| Enterprise | 90-365 дней | 15-25% | $100k-1M+ |
| Strategic / 7-figure | 365+ дней | 30-40% (high consideration) | $1M+ |

## Goal mode: «нам нужно $1M ARR за квартал — что менять?»

Quarterly target: $1M ARR.
Per-day velocity нужна: $1M / 90 = $11.1k.

Current: $5k/day. Нужно поднять в **2.2×**.

Способы:
- Hire ещё одного AE → +30 opportunities → velocity 6.5k. Недостаточно.
- + pricing review (+15% ACV) → 7.5k. Ещё недостаточно.
- + ICP-cleanup (Win Rate 25→32%) → 9.6k. Близко.
- + reduce avg cycle 60→50d → 11.5k. **Reach target.**

Combination of 4 small improvements (each ~15%) > one big push на one lever.

## Как использовать в weekly forecasting

Каждую неделю обновляй:
- Pipeline value
- Stage-weighted opportunity count
- Last 4 quarters average Win Rate
- Last 4 quarters average cycle length

Velocity × remaining days в quarter = forecast. Сравни с quota gap.

Это лучше чем classic «pipeline × probability» (которое забывает время и cycle).

## Связь с другими B2B-метриками

| Метрика | Связь |
|---------|-------|
| **Pipeline Coverage** | Coverage 3-4× нужно для Velocity (without enough opps, velocity caps) |
| **Win Rate** | Один из 4 факторов |
| **CAC Payback** | Velocity × ACV / S&M expense → CAC ratio |
| **Sales Cycle Length** | Один из 4 факторов |

## Итог

Sales Velocity = **главная B2B-формула** которая объединяет 4 leading indicators в одну выручку-проектирующую цифру. Знай свою. Найди один-два рычага с наибольшим current room-to-improve и работай по нему. Не пытайся улучшать всё параллельно.
